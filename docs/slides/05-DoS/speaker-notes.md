# Lecture 5 — Speaker Notes (Denial of Service Attacks)

Per-slide context + clickable links. In-deck notes (the `::: {.notes}` blocks) are also visible via reveal.js speaker view (press **S**). Every URL was verified this session or is a canonical org landing page.

| Slide | Context + Links |
|---|---|
| **From System Security to Internet Security** | Divider. Frame the shift from confidentiality/integrity (crypto, auth) to **availability** — the A in CIA. DoS is the first attack this term where the adversary never has to compromise the target's data. Good cold-call: "which is worse for a bank on payday — a leaked file, or a site that's down?" |
| **A Recent Hook: The Biggest Attack Ever Recorded** | **Primary sources for the 31.4 Tbps record:** Cloudflare's [Q4 2025 DDoS Threat Report (blog, Feb 2026)](https://blog.cloudflare.com/ddos-threat-report-2025-q4/) · full report on [Cloudflare Radar](https://radar.cloudflare.com/reports/ddos-2025-q4) · [The Hacker News coverage (Feb 2026)](https://thehackernews.com/2026/02/aisurukimwolf-botnet-launches-record.html) · [SecurityAffairs](https://securityaffairs.com/187690/hacking/record-breaking-31-4-tbps-ddos-attack-hits-in-november-2025-stopped-by-cloudflare.html). The attack was launched in **November 2025**, mitigated autonomously in seconds. **Aisuru/Kimwolf botnet (TurboMirai family):** [Cloudflare learning page](https://www.cloudflare.com/learning/ddos/glossary/aisuru-kimwolf-botnet/) · [Cloudflare Q3 2025 report](https://blog.cloudflare.com/ddos-threat-report-2025-q3/) puts the infected-host estimate at **1–4 million**, primarily off-brand Android TV set-top boxes. **March 19, 2026 international takedown:** [DoJ press release, District of Alaska](https://www.justice.gov/usao-ak/pr/authorities-disrupt-worlds-largest-iot-ddos-botnets-responsible-record-breaking-attacks) · [Help Net Security](https://www.helpnetsecurity.com/2026/03/20/us-disrupts-iot-botnets-ddos-attacks-aisuru-kimwolf/) · [The Hacker News](https://thehackernews.com/2026/03/doj-disrupts-3-million-device-iot.html). DoJ, German BKA, and Canadian authorities coordinated seizure of C2 for Aisuru, Kimwolf, JackSkid, and Mossad — 3M+ infected devices, hundreds of thousands in the US. **Callback:** Aisuru also took down [Krebs on Security in May 2025 at 6.35 Tbps](https://krebsonsecurity.com/) — Krebs was Mirai's most famous target in 2016, closing the loop. **Coda for notes:** [FastNetMon (Mar 2026)](https://fastnetmon.com/2026/03/20/aisuru-and-kimwolf-disrupted-but-the-botnet-cycle-continues/) warned scanning from new infrastructure was observed within weeks — the takedown cycle repeats. |
| **Denial of Service: What Is It?** | Keep intuitive: DoS **exhausts a limited resource**. Every layer has one — bandwidth (network), TCB slots (transport), CPU (application). "Distributed" (DDoS) just means many sources at once. Cheap application-layer requests can hurt more than gigabits. |
| **Targets of Attack** | The strategic insight: attack the *dependency*, not the target. **DNS** as force multiplier sets up the Dyn case study. **Authentication** as target (Duo, Okta) is a live 2026 concern — if 2FA is down, no one logs in. [The Okta Oct 2023 support-system breach](https://sec.okta.com/harfiles) is the reference for "the auth provider is now a single point of failure." |
| **Three Common Characteristics** | Explicitly midterm-flagged in the agenda. **Asymmetry** is the deepest idea — it's the lens for the rest of the lecture. **Indistinguishability** (real traffic looks the same as attack traffic when botnet-sourced) and **unattributability** (IP source spoofing, [RFC 2827 / BCP 38](https://datatracker.ietf.org/doc/html/bcp38)) fall out of botnets and reflection for free. Drill all three. |
| **Asymmetry, Concretely** | The unifying principle. Every attack in the deck (SYN flood, DNS amp, TLS DoS) is a different way to make victim cost >> attacker cost. Every defense in the deck (SYN cookies, ingress filtering, scrubbing) is a way to *restore* symmetry — or, as the stateful-firewall slide shows, to create a new asymmetric resource for the attacker to exhaust. |
| **Case Study: Mirai and the Dyn Attack** | **Oct 21, 2016 Dyn attack:** [Wikipedia summary](https://en.wikipedia.org/wiki/DDoS_attack_on_Dyn) · [Dyn's own post-mortem](https://www.dynstatus.com/incidents/nlr4yrr162t8). Three waves; Twitter, Netflix, Spotify, Reddit went dark for hours. Mirai's source code was released on Hack Forums in September 2016 by "Anna-Senpai" — [Krebs' investigation](https://krebsonsecurity.com/2016/09/who-is-anna-senpai-the-mirai-worm-author/) — which is exactly why descendants (Aisuru/Kimwolf) still exist. Attack peaked around 1.2 Tbps. The strategic move: hit **Dyn**, not the sites. |
| **Why a "Small" Botnet Hurt So Much** | The richest teaching moment. Two lessons: (1) **attacking infrastructure creates cascade failures** across many downstream services; (2) **resilience mechanisms can amplify attacks** — legitimate clients' automatic retries generated 10–20× normal traffic (the "death spiral"). This is characteristic #2 (indistinguishability) at its purest — legitimate users' clients were adding to the flood. |
| **Reflection and Amplification** | Draw it on the board: attacker → resolver (small, spoofed) → victim (large). **Amplification factor table for the board or breakout:** DNS ~28–54×, NTP ~556×, memcached ~10,000–51,000× ([US-CERT TA14-017A on NTP](https://www.cisa.gov/news-events/alerts/2014/01/13/ntp-amplification-attacks-using-cve-2013-5211)). Memcached is the [Feb 2018 1.35 Tbps GitHub attack](https://github.blog/2018-03-01-ddos-incident-report/). The agenda flags "given a reflection diagram, explain how it works" as likely midterm — make sure everyone can reproduce this flow. |
| **Open Resolvers and Misaligned Incentives** | Policy/economics dressed as tech. Open resolvers by design: [Google Public DNS](https://developers.google.com/speed/public-dns), [Cloudflare 1.1.1.1](https://one.one.one.one/). Misconfigured ones: [Open Resolver Project](https://openresolverproject.org/). The externality — you'd secure your server to protect someone else — is the same shape as BCP 38 (next lecture's routing story too). Bridge to activity: this is the mechanism the [DoS / Botnets breakout](../../breakouts/dos-botnets.md) argues about (regulate the IoT externality). |
| **TCP SYN Flooding** | Cleanest illustration of asymmetric state allocation: one ~40-byte SYN costs the server a ~280-byte record it must hold until timeout. Agenda notes we treat this lightly, but it's the setup for the SYN-cookie defense two slides later. Historical example (notes-only): MS Blaster (2003) SYN-flooded windowsupdate.com. [SYN flood — Wikipedia](https://en.wikipedia.org/wiki/SYN_flood). |
| **Application-Layer and Crypto DoS** | "You don't need gigabits if each request is cheap to send and expensive to serve." **TLS handshake DoS:** RSA decrypt ~10× costlier than encrypt — one attacker box can overwhelm ~10 servers ([THC-SSL-DoS demo, 2011](https://en.wikipedia.org/wiki/THC-SSL-DOS)). Aisuru's Q4 2025 [200 Mrps HTTP flood campaign ("The Night Before Christmas")](https://blog.cloudflare.com/ddos-threat-report-2025-q4/) is the current example of application-layer at scale. |
| **Defenses (divider)** | The test for every defense: *have I introduced a new resource to exhaust?* |
| **Defense: Ingress Filtering (BCP 38 / RFC 2827)** | [BCP 38 / RFC 2827 (Ferguson & Senie, 2000)](https://datatracker.ietf.org/doc/html/bcp38). Still not universally deployed after 25+ years — pure externality problem. Measurement: [CAIDA Spoofer project](https://spoofer.caida.org/) publishes ongoing spoofability estimates. Great "should this be technical, market, or regulatory?" prompt — it's the entry point to the [DoS/Botnets breakout, Breakout A](../../breakouts/dos-botnets.md) on IoT liability. |
| **Defense: SYN Cookies** | Canonical "make the initiator do work first" defense — same shape as cryptographic proof-of-work / proof-of-reachability puzzles. Cookie = `HMAC(time, nonce, src/dst IP+port)` encoded into the SYN-ACK sequence number. Server stores *nothing* until the client returns a valid ACK. Origin: [D. J. Bernstein's SYN cookies page](https://cr.yp.to/syncookies.html). Trade-off: a few TCP options can't be carried during the handshake, but the server survives the flood. |
| **When Defenses Backfire: Stateful Firewalls** | The lecture's punchline and a likely midterm cold-call ("how would you attack the stateful firewall? what packets would you send?"). Meta-lesson: security features can introduce vulnerabilities. Mitigation loops back to ingress filtering — don't let spoofed packets reach the firewall in the first place. |
| **Defense: uRPF and Its Limits** | Router-level cousin of ingress filtering. Cisco syntax `ip verify unicast reverse-path` — [Cisco uRPF overview](https://www.cisco.com/c/en/us/about/security-center/unicast-reverse-path-forwarding.html). Strict uRPF breaks with modern asymmetric routing (path in ≠ path out); looser modes exist but are weaker. Real defense is layered. |
| **Operational Defenses: The Mirai/Dyn Playbook** | Anycast — how the [DNS root survives](https://root-servers.org/) despite [regular attacks (2007, 2015)](https://www.icann.org/en/system/files/files/dns-attack-15dec06-en.pdf). Third-party scrubbing (Cloudflare, Akamai, Google Shield) has become the dominant commercial defense. Note the **centralization/policy implication** — the [Nov 18, 2025 Cloudflare outage](https://blog.cloudflare.com/18-november-2025-outage/) reminded everyone what depends on Cloudflare. This is the setup for [Breakout B on scrubbing as common-carrier infrastructure](../../breakouts/dos-botnets.md). Cloudflare's Q4 2025 report: **~5,376 mitigations per hour** across 2025. |
| **Weaponizing the Network: China's Great Cannon** | **Corrected date: March 2015, not 2016.** Primary sources: [Citizen Lab, "China's Great Cannon" (Apr 10, 2015)](https://citizenlab.ca/2015/04/chinas-great-cannon/) · [Marczak, Weaver et al., USENIX FOCI '15 analysis (PDF)](https://www.usenix.org/system/files/conference/foci15/foci15-paper-marczak.pdf) · [Krebs, "Don't Be Fodder for China's Great Cannon" (Apr 2015)](https://krebsonsecurity.com/2015/04/dont-be-fodder-for-chinas-great-cannon/). Timeline: [Google Safe Browsing timeline](https://www.helpnetsecurity.com/2015/04/27/how-google-saw-the-ddos-attack-against-github-and-greatfire/) shows GreatFire hit Mar 16, GitHub Mar 26, injection ended Apr 7. Distinguish from the Great Firewall (which only blocks) — the Cannon *injects*. Most-injected domain was `pos.baidu.com`. Attacking "clients" were located worldwide (TW, HK, US, MY), making attribution and filtering hard. Good bridge to the [Backdoors debate](../../debates/backdoors.md) scheduled this day: state actors already weaponize the network path — what does adding backdoors to *endpoints* add or subtract? |
