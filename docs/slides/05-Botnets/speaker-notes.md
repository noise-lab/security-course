| Slide | Context + Links |
|---|---|
| **From System Security to Internet Security** | The course-arc pivot: from host/protocol trust to million-machine adversaries. Set up in `agenda.md` §Meeting 3 "Theme Shift: From System Security to Internet Security." Frame today's question: how do you *build* a million-machine weapon, and what does it cost the target? |
| **What Is a Denial-of-Service Attack?** | Canonical taxonomy: [RFC 4732 — Internet Denial-of-Service Considerations (2006)](https://datatracker.ietf.org/doc/html/rfc4732). Three resource classes: network bandwidth, connection state, server compute. Cold-call: "what's the scarcest resource in a TLS handshake?" (server-side asymmetric key generation, per [Cloudflare — TLS handshake performance](https://blog.cloudflare.com/keyless-ssl-the-nitty-gritty-technical-details/)). |
| **Common Targets** | DNS as the highest-leverage infrastructure target foreshadows the Dyn case. [Duo's 2FA / Cisco Duo](https://duo.com/) was named in the agenda as an example of an authentication service that has been DoS'd. Update servers as attack targets: see [Kaseya 2021 supply-chain incident](https://www.cisa.gov/news-events/analysis-reports/ar21-189a) for a related "block the patches" pattern. |
| **Three Characteristics of Every DoS Attack** | The analytical spine of the lecture — flagged as midterm material in `agenda.md`. Reference: [Mirkovic & Reiher, "A Taxonomy of DDoS Attack and DDoS Defense Mechanisms" (SIGCOMM CCR 2004)](https://dl.acm.org/doi/10.1145/997150.997156). Tell students: for any new DoS attack, exam question = "which of the three, and how?" |
| **1. Asymmetry** | Small packet → large state allocation is the [SYN flood pattern (RFC 4987)](https://datatracker.ietf.org/doc/html/rfc4987). Small request → expensive crypto = the [TLS renegotiation attack (CVE-2011-1473)](https://nvd.nist.gov/vuln/detail/CVE-2011-1473). Amplification via protocol vs botnet scale = two different asymmetry sources. |
| **2. Hard to Distinguish Attack From Legit** | The million-source problem. Empirical grounding: [Cloudflare 2025 Q4 DDoS Threat Report](https://blog.cloudflare.com/ddos-threat-report-2025-q4/) — 47.1M attacks in 2025, 5,376/hour average, up 121% YoY. |
| **3. Hard to Attribute** | IP source spoofing = the enabling primitive. [RFC 2827 / BCP 38 — Network Ingress Filtering (2000)](https://datatracker.ietf.org/doc/html/bcp38). Current deployment measurement: [CAIDA Spoofer project](https://spoofer.caida.org/). Note: TCP-based attacks can't fully spoof (need SYN-ACK back) — useful contrast for later stateful-firewall slide. |
| **Worms vs. Viruses** | Definitions: [NIST SP 800-83 — Guide to Malware Incident Prevention (Rev 1, 2013)](https://csrc.nist.gov/publications/detail/sp/800-83/rev-1/final). **Morris worm (Nov 2, 1988):** [ACM classic paper — Spafford, "The Internet Worm Program: An Analysis"](https://dl.acm.org/doi/10.1145/66093.66095) · [Wikipedia](https://en.wikipedia.org/wiki/Morris_worm). First [CFAA (Computer Fraud and Abuse Act, 18 U.S.C. §1030)](https://www.law.cornell.edu/uscode/text/18/1030) prosecution — *United States v. Morris* (1990). |
| **Worms Go Mainstream: 2001–2003** | **Code Red (Jul 2001):** [CERT Advisory CA-2001-19](https://resources.sei.cmu.edu/library/asset-view.cfm?assetid=496151) · [Moore, Shannon, Voelker, Savage — "Code-Red: a case study" (IMW 2002)](https://www.caida.org/catalog/papers/2002_codered/codered.pdf). **Nimda (Sep 2001):** [CERT Advisory CA-2001-26](https://resources.sei.cmu.edu/library/asset-view.cfm?assetid=496212). **Slammer (Jan 2003):** [Moore et al., "The Spread of the Sapphire/Slammer Worm"](https://www.caida.org/catalog/papers/2003_sapphire/sapphire.html). |
| **Slammer in 30 Minutes** | Same [CAIDA Sapphire/Slammer paper](https://www.caida.org/catalog/papers/2003_sapphire/sapphire.html). 8.5-second doubling; ~$1.25B damage estimated by [Computer Economics](https://www.computereconomics.com/). Notably knocked out B of A ATMs, a Korean cell network, five root DNS servers, and Continental Airlines ticketing — with no malicious payload. |
| **What Is a Botnet?** | Canonical treatment: [Rajab, Zarfoss, Monrose, Terzis, "A Multifaceted Approach to Understanding the Botnet Phenomenon" (IMC 2006)](https://dl.acm.org/doi/10.1145/1177080.1177086). Modern DDoS-for-hire ("booter") market: [Krebs on Security — recurring booter takedowns](https://krebsonsecurity.com/category/ddos-for-hire/) · [FBI's Operation PowerOFF (recurring joint takedowns)](https://www.europol.europa.eu/media-press/newsroom/news/power-off-27-ddos-for-hire-services-taken-down-in-largest-ever-operation). |
| **Command and Control (C&C)** | Centralized vs P2P C&C = the design tradeoff. [Storm (2007)](https://en.wikipedia.org/wiki/Storm_botnet) forced defenders to poison the overlay. Fast-flux DNS: [ICANN SSAC SAC 025](https://itp.cdn.icann.org/en/files/security-and-stability-advisory-committee-ssac-reports/sac-025-en.pdf). |
| **Mirai (2016): The IoT Turn** | [Antonakakis et al., "Understanding the Mirai Botnet" (USENIX Security 2017)](https://www.usenix.org/conference/usenixsecurity17/technical-sessions/presentation/antonakakis) — canonical measurement study. [Mirai source code (Anna-Senpai release, Sep 2016)](https://github.com/jgamblin/Mirai-Source-Code). Krebs's own writeup: [Krebs on Security — "Who Is Anna-Senpai, the Mirai Worm Author?"](https://krebsonsecurity.com/2017/01/who-is-anna-senpai-the-mirai-worm-author/). |
| **Case Study: Mirai vs. Dyn, October 2016** | Oct 21, 2016 attack. [Dyn post-mortem — "Dyn Analysis Summary Of Friday October 21 Attack"](https://web.archive.org/web/20161028024649/https://dyn.com/blog/dyn-analysis-summary-of-friday-october-21-attack/) · [Wikipedia summary](https://en.wikipedia.org/wiki/2016_Dyn_cyberattack). Not the biggest by traffic — the *leverage* was in hitting DNS infrastructure for Twitter/Netflix/Spotify/Reddit at once. |
| **The Death Spiral** | The retry-storm dynamic — the resilience feature (auto-retry) becomes the amplifier. Documented in the [Dyn post-mortem](https://web.archive.org/web/20161028024649/https://dyn.com/blog/dyn-analysis-summary-of-friday-october-21-attack/): "a legitimate response to malicious activity … 10-20 times more DNS traffic than what was actually consumed by the botnet." Cold-call: "you're Dyn's on-call at 3am — what do you do?" |
| **A 2026 Bookend: Mirai's Descendants** | **All figures verified this session.** **31.4 Tbps attack, Nov 2025, 35 seconds:** [Cloudflare 2025 Q4 DDoS Threat Report](https://blog.cloudflare.com/ddos-threat-report-2025-q4/) — publicly disclosed late Jan 2026. **"Night Before Christmas" campaign, Dec 19, 2025, 200M+ HTTP req/s peak:** same Cloudflare report; also [The Hacker News — Aisuru/Kimwolf 31.4 Tbps](https://thehackernews.com/2026/02/aisurukimwolf-botnet-launches-record.html). **Aisuru/Kimwolf composition — 2M+ Android TVs, off-brand set-top boxes:** [XLab Kimwolf technical writeup (Dec 2025)](https://blog.xlab.qianxin.com/) · [Cloudflare Aisuru-Kimwolf glossary](https://www.cloudflare.com/learning/ddos/glossary/aisuru-kimwolf-botnet/). **March 19, 2026 DoJ / District of Alaska takedown of Aisuru, Kimwolf, JackSkid, Mossad — ~3M devices, coordinated with Canada, Germany, Netherlands, EUROPOL:** [DoJ / USAO-AK press release](https://www.justice.gov/usao-ak/pr/authorities-disrupt-worlds-largest-iot-ddos-botnets-responsible-record-breaking-attacks) · [Krebs on Security — Feds Disrupt IoT Botnets](https://krebsonsecurity.com/2026/03/feds-disrupt-iot-botnets-behind-huge-ddos-attacks/) · [The Hacker News — DoJ 3M-device takedown](https://thehackernews.com/2026/03/doj-disrupts-3-million-device-iot.html) · [Team Cymru writeup](https://www.team-cymru.com/post/team-cymru-doj-iot-ddos-botnet-disruption). Private-sector assistance: Akamai, AWS, Cloudflare, DigitalOcean, Google, Lumen, Nokia, Okta, Oracle, PayPal, SpyCloud, Team Cymru, Unit 221B, QiAnXin XLab. **"Dort"/Jacob Butler arrest, May 20, 2026, Ottawa (extradition warrant, 10-year max):** [TechNadu coverage of KimWolf admin arrest](https://www.technadu.com/canadian-administrator-arrested-following-kimwolf-ddos-botnet-takedown/628296/). Escalation curve: 5.6 Tbps (Oct 2024) → 7.3 Tbps (Jun 2025) → 15.72 Tbps (Oct 2025, Microsoft) → 31.4 Tbps (Nov 2025). |
| **DNS Reflection and Amplification** | Classic writeup: [US-CERT TA13-088A — DNS Amplification Attacks (Mar 2013)](https://www.cisa.gov/news-events/alerts/2013/03/29/dns-amplification-attacks). Amplification factors: [US-CERT/ICS-CERT table — DNS ~28–54×, NTP ~556×, SSDP ~30×, memcached ~10,000–51,000×](https://www.cisa.gov/news-events/alerts/2014/01/17/udp-based-amplification-attacks). Historic peaks: [GitHub 1.35 Tbps memcached attack, Feb 2018](https://github.blog/2018-03-01-ddos-incident-report/). Open resolvers historical scan data: [Open Resolver Project](http://openresolverproject.org/) (Rossow/Kührer). |
| **Defense, and Its New Vulnerability** | Stateful-firewall-as-target = "any defense requiring state introduces a new attack surface" — the day's second midterm-flagged principle. Root-cause fix: [BCP 38 / RFC 2827 — Ingress Filtering](https://datatracker.ietf.org/doc/html/bcp38). Deployment status: [MANRS (Mutually Agreed Norms for Routing Security)](https://www.manrs.org/) tracks source-address-validation adoption. Related refresh — [CAIDA Spoofer](https://spoofer.caida.org/) shows spoofable-network share still ~15–20% of tested ASes in 2025. |
| **Defenses: Monitoring and Takedown** | IRC-C&C monitoring history: [Freiling, Holz, Wicherski, "Botnet Tracking" (ESORICS 2005)](https://link.springer.com/chapter/10.1007/11555827_19). Honeypots: [Provos & Holz, *Virtual Honeypots* (2007)](https://www.honeynet.org/). Modern C&C sinkholing tradeoff — hijack C2, bots go dark but so does your visibility (see [Kaspersky Zeus/GameOver sinkholing 2014](https://securelist.com/gameover-zeus-and-the-fbi/)). The Aisuru March 2026 takedown (see prior slide) is the modern coordinated model. |
| **What to Take Away** | The photograph-this-slide summary. If students remember the three characteristics + "any stateful defense is a potential DoS target," they can reason about any attack they've never seen.
